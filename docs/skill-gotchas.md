# Skill gotchas (one line each: reference file, then the fact)

- references/platform-gba.md: keystone (KS_MODE_THUMB) assembles `nop` as Thumb-2 0xBF00, which the GBA's ARMv4T doesn't have (the game hung in a loop); pad in-place patches with `mov r8, r8` (0x46C0). capstone/disasm.py prints 0xBF00 as `nop`, so a disassembly check doesn't catch it.
- references/emulator-qa.md (Savestates): a player's RetroArch/mGBA GBA state (RZIP -> RASTATE -> MEM block = mGBA GBASerializedState, 0x61000 bytes) runs in Mesen by injecting IWRAM/EWRAM/VRAM/OAM/palette/display IO and the CPU regs over a same-mode Mesen state at endFrame (both at VCOUNT 160), with `cpu.r15` = mGBA r15 - 4 (Thumb) and `cpu.pipeline.reloadRequested`: tools/mgba_state.py + tools/lua/mgba_load.lua in the Goushouden repo (worth a skill script like s9x_state.py).
- references/graphics.md (Survey): sheets that draw a block's tiles in linear 8x8 order hide text in 16x16 / 32x16 OBJs (a whole クリティカル!! / ミス popup was missed and shipped Japanese twice); where sprite-frame records exist, assemble the frames (Goushouden tools/objsweep.py) before reviewing.
- references/emulator-qa.md (Debug tool / msgview): a forced-message viewer can hide a bug that depends on the scene's own window: the speaker tag's odd-length clip didn't show in msgview's window but did in the field, so reproduce a player's report from their state, not only through the viewer.

- references/graphics.md: a static sweep of a GBA game with thousands of packed blocks needs a tilemap filter (u16 entries: few high-byte values, many low-byte values); without it 6,196 of 9,645 blocks were stripe noise and the sheets ran to 97 pages.
- references/graphics.md: `codex exec -i` reviewers saw no text on full 1056 px sweep pages; cutting each page into quarters zoomed 2x fixed it, but two passes still disagreed on 45 of 167 hits and both missed one block found by eye. Run two passes and take the union.
- references/emulator-qa.md: `codex exec -i a.png b.png "prompt"` swallows the prompt as an image path; pass images comma-separated and the prompt on stdin (`-`).
- references/pipeline.md (Recon, compression): hooking the unpacker's copy-out point (decoder done, before copy to dst) and dumping the temp buffer gave ground truth for writing two unknown codecs from disassembly; both matched on the first test run.
- references/pipeline.md (Recon, compression): a codec may read before the start of its output buffer (this game's type 3 expects zeros there); a decoder that raises on such a back-reference rejects real blocks.
- references/emulator-qa.md (Debug tool): a GBA game's leftover debug menu was re-enabled from Lua alone: patch one BL in emulator ROM memory (emu.write ... gbaPrgRom) and pick menu rows by emu.setState r0 at the menu routine's return; no ROM patch file needed.
- references/emulator-qa.md (emu.py): 6 parallel Mesen runs (warp_all --jobs 6) put the machine under memory pressure and Claude Code killed the background job; use 2-3 jobs.
- references/emulator-qa.md (emu.py): --route plus a --script that presses keys itself (warp.lua's A nudges) interleave in one input queue and shift every menu step; put extra presses into the scene's own steps (press=B) instead.
- references/emulator-qa.md (Debug tool): reaching game over by writing HP 0 failed (battles ignore it, units only fall to real damage); pinning the enemies' HP with the party at 1 HP and mashing attack worked. Battle records were heap-allocated and moved between a savestate and a cold boot: find them by a signature each run, never a fixed address.
- references/emulator-qa.md (emu.py): even warp_all --jobs 2 was killed by Claude Code's low-memory guard when other repos' Mesen instances shared the machine; check free memory first and use --jobs 1 on a busy machine.
- SKILL.md Step 0 (template .gitignore): the unanchored `rom/` line also ignored `script/rom/`, so 1,849 extracted ROM strings were never committed through phase 4; anchor top-level dirs (`/rom/ /build/ /work/ /dist/ /release/`) in the template.
- references/pipeline.md (Marker build): the game's ASCII -> fullwidth conversion table looked like text (fullwidth `！”＃…` rows, pointed from a table) and was extracted; marking it blanked every box. Before the marker build, check for tables whose rows are the ASCII/fullwidth sequence and mark them data.
- references/platform-gba.md: Thumb BL reaches only +-4 MiB, so hooks for code in the first MiBs can't sit past 8 MiB; relocating a big block (here the script archive) to the expansion frees near space for hooks.
- references/emulator-qa.md (sheet.py): --out into a directory that doesn't exist raises FileNotFoundError; it should mkdir the parent.
- references/emulator-qa.md (emu.py): a --route given together with a warp.lua --script overrides the warp's own input from frame 0; save a state with STATE_OUT/HOLD and run the route from --state-in instead.
- references/pipeline.md (Marker build): a marker scene that hangs only with ALL marker strings (each half passes alone) was heap corruption: a centred line wider than its window got a negative x and the glyph blitter wrote before its malloc'd buffer. Bisection can't find a pair across halves; trace the hang (PC sample -> malloc's out-of-memory spin -> walk the free list -> watch the clobbered header). Clamp the cursor x in the engine.
- references/pipeline.md (Marker build): marker text in a window that draws plain ASCII through a different writer can be invisible (pen advances, VRAM gets ink, nothing shows: the book window here); compare fullwidth and ASCII in the same box before measuring it.
- references/emulator-qa.md (Visual QA): warp timing shifts a few frames between builds (string lengths change VWF cost), so a single fixed-frame shot can land on a window's opening frame and show it empty: a "blank list on the marker build" was this. Scan a frame range (or diff ink over frames) before calling a box blank; `tools/bisect_marker.py --ink FRAME:BOX` bisects a visual predicate but inherits the same trap.
- references/translation.md (Translator dispatch): in an Orca-dispatched Claude Code worker the plugin's agent types (`translate-retro-game:translator`) were not registered (the plugin's skill was not listed either), so translators ran as general-purpose with the brief path in the prompt. Copying `agents/*.md` into the repo's `.claude/agents/` would register them for the next session.
- references/translation.md (Batch design): for a fixed 2-line dialogue box that scrolls, let translators write sentences and have `batches.py` word-wrap each page at merge (`tools/batches.py fit`); the speaker line comes from a name-tag table (`tools/speakers.tsv`), not from translators.
- assets/batches.py (check): an archive message that is only a name tag (JP body empty, e.g. "研究員\n") is still batched, and `check` refuses empty English; it then also wants the trailing blank, so the only passing output is "...\n". `split` should skip entries whose shown JP body is empty (the rule already exists for wholly empty JP).
- references/translation.md (Translator dispatch): an Orca worker brief says "no subagents", so a 54-batch dialogue wave ran in one worker context (~8k tokens per batch); plan worker hand-offs at ~15 batches each when subagents are off.
- references/translation.md (Review): with no nested workers (Orca), a read-only `codex exec -s read-only` per batch (tools/review.sh, ~80 s a batch) did the reviewer pass; six codex processes at once ran a 16 GB host low on memory and the host killed the run: use 3. Reviewer name findings are only as good as the name source: the ROM's own kana short-name records (e.g. 鬼谷 then きたに) settled readings that the glossary, speakers.tsv and wave 1 disagreed on; point reviewers and translators at them first.
- assets/batches.py (check): the honorific rule matched 名前+君 across a line break in "僕は 不動明\n君達は" (君達 = "you all"); skip 君達/君たち.
- references/pipeline.md (Checks) / assets/batches.py: a field-width short form (D4 last resort) fails the glossary rule forever; a per-id keep file (`script/short_forms.tsv`, id + exact English) that the glossary check honours keeps the rule strict everywhere else. Relocating overlong pointer-reached strings in build.py (assert each site holds the old address, write after the archives, repoint) lifted 185 byte limits at once; wave-1 translators had abbreviated to bytes that were only "in place" limits, so have the lint treat bytes as soft when a string has pointers from the start.
- references/graphics.md (Survey): sprite-font blocks (one big glyph per block, e.g. SFX cut-in kana) look like 'title card lettering' in the sweep; check for a char->glyph lookup table first, then redraw the font + lookup codes instead of every word. Count what the drawer shows with an OAM log (here 4 sprites max), not the name length.
- scripts/ramsearch.py (GBA): a probes/ramdump.lua dump is EWRAM (256K) then IWRAM (32K), but --base 0x02000000 labels the IWRAM half 0x0204xxxx; real address = 0x03000000 + (label - 0x02040000). Teach --base a per-system layout.
- references/graphics.md (Lettering, map signs): gfxlabel-style 'copy the label into every block holding the same tiles' is wrong for map tile sets: another set's different sign shared 2-3 glyph tiles and got garbled (間身井薬局 on maps 309/310); turn the copy off for map signs and give each tile set its own entry.
- references/emulator-qa.md (emu.py, --var): probe vars share one global namespace with emu.py's own globals (SHOTS, OUT, FRAMES...) and with other probes (mash.lua's FROM): a probe var named SHOTS hung the run with an empty log. Prefix probe vars (MV_FROM, MV_SHOTS); emu.py could reject --var names it already sets.
- references/emulator-qa.md (Text coverage, compressed text): for an lh5-packed script archive, put each message's u16 id-map entry address in strings.tsv: the lookup reads it on every display, so textcover.lua catches it with no writer hook. A forced viewer (swap r0 at the lookup's entry, reload a state before a short event when it runs dry) shows every message at ~200 frames each.
- SKILL.md (Wait on long runs): Claude Code kills idle background shells under memory pressure; Mesen GBA takes ~1 GB per instance, so 3 emulators + codex on a 16 GB machine got both long runs killed. Run one long job at a time.
- references/emulator-qa.md (emu.py, --var): a --var string value needs Lua quotes ("FV_IF='r1=0x0882F430'"); unquoted, the generated _run.lua fails to parse and emu.py sits to its timeout (124) with no log.txt at all, rather than exiting 2.
- references/emulator-qa.md (Text coverage): for ROM strings no tour reaches (data-table names, unreachable prompts), hook the menu printer's entry (here 0x0800E3D0, r1 = string) in a list screen and swap the string pointer per call with a LOOP state reload: ~13 strings per reload, 1,332 strings in minutes (tools/forcestr.py). Proves read + drawn, not own-box fit.
- references/graphics.md (Survey): a label the game loads but never displays (a tab with no slot, a pill needing suspend data) can be evidenced by unpackat (block -> VRAM dst on the EN build) + ppudump + tiles.py render; block tiles are often not row-major, so pick cols per block.
- references/translation.md (Review, story pass): a codex reviewer reading a ~50 KB chapter file goes through the context-mode hook, which cuts large reads; inline the chapter into the prompt (tools/story_review.sh) and ask it to state how many entries it read. Take speaker tags from the shipped text, not the batch files: stale batch tags produced false "wrong name" findings.
- references/emulator-qa.md (Text coverage): text-coverage logs are tied to string addresses; a late text fix that grows a packed archive moves everything after it (other archives, relocated ROM strings), and stale logs then miss or falsely hit ids. Diff build/*.strings.tsv before and after and re-force only the moved ids.
